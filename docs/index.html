MIT 授權Node.js 22+Muse Code 1.3.0 已驗證

這是獨立的社群 plugin。它在你的電腦上啟動官方 muse serve，把 Muse 的回覆、核准選項與用量資料帶回 Codex。套件包含可重複使用的 Muse skill 和本機 MCP server。

先確認使用通道

Bridge 只在 Muse 回報 accountLogin 時允許模型回合。啟動前會複製環境設定，只從 muse serve 子程序的副本移除 META_API_KEY 與 MODEL_API_KEY；父程序、shell、環境檔與已存 credential 都維持原樣。你的訂閱資格與限額仍由 Meta 決定。

01

安裝與登入

準備 Node.js 22 或更新版本、官方 Muse Code CLI，以及具有適用訂閱資格的 Meta 帳號。

  1. 安裝 Muse Code，完成瀏覽器登入

    依照 Meta 官方文件安裝 CLI，再於 Terminal 執行下列指令。授權頁請選擇擁有訂閱的 Meta 帳號。

    Terminal
    muse --version
muse login
node --version

  2. 加入 marketplace 並安裝 plugin

    Codex CLI
    codex plugin marketplace add stts0919/Muse-Code-Bridge-plugin
codex plugin add muse-code-bridge@muse-code-bridge-public

    也可以在 Codex 的 plugin 目錄選擇 Muse Code Bridge Public，再安裝 Muse Code Bridge。

  3. 開啟新的 Codex task

    讓新安裝的 skill 和 MCP tools 載入。Repo 已附上打包好的 server，這條安裝路徑不需要執行 npm install。

桌面 App 的環境必須能找到 node 和 muse。若 Muse 不在 App 的 PATH，可在本機 MCP 環境設定 MUSE_BIN；個人執行路徑留在本機即可。

02

第一次使用

從 / skill 選單選擇 Muse，或直接告訴 Codex：

Codex 對話
使用 $muse-code-bridge 開啟這個 task 的 Muse 模式。

當 skill 收到純文字 /Muse，也會啟用相同流程。開啟後，同一 task 的實質任務會交給目前 workspace 保留的 Muse session，回覆會標示為 Muse Code:。

先試一個唯讀任務

試用提示詞
請閱讀這個 workspace，說明程式進入點與啟動方式，先不要修改檔案。

Muse 要求核准或提出問題時，Codex 會顯示原始操作與選項。由你明確決定，skill 不會代選核准。要回到一般 Codex 處理，輸入 /MuseOff，或說「離開 Muse 模式」。

對話轉交的方式

Muse 模式由 Codex 遵循 skill／prompt 指令來運作；它會呼叫本機 Muse，Codex 本身的模型供應商維持原有設定。不同 client 的 slash command 選單可能不同。

03

用量監控

在同一個 Codex task 輸入：

查詢用量
顯示 Muse Code 用量

Bridge 會讀取 Muse 回報的使用視窗，顯示已使用百分比、剩餘百分比與重置時間。支援 MCP Apps 的 client 可以顯示用量 widget；其他 client 可查看文字回覆。

  • 這是當下的觀測值，沒有資料時會明確顯示未提供。
  • 百分比不能自行換算成 token 或剩餘提示詞數。
  • 時間依顯示端的本機語系與時區呈現。
04

其他 MCP 環境

七個 MCP tools 可接入支援本機 stdio MCP 的 client，例如 Claude Code 或 VS Code 中適用的 MCP 工具。自動 Muse 模式與用量 widget 則取決於 client 的 skill、prompt 和 MCP Apps 支援。

先 clone Repo，再把以下示範路徑換成你電腦上的位置。設定檔位置請依各 client 的文件操作。

MCP 設定範例
{
  "mcpServers": {
    "muse-code-bridge": {
      "command": "node",
      "args": ["/absolute/path/to/Muse-Code-Bridge-plugin/plugins/muse-code-bridge/dist/server.mjs"]
    }
  }
}

只複製 SKILL.md 會提供操作指引；實際呼叫 Muse 仍需要 MCP server。

05

工具一覽

Tool用途
get_muse_status查看執行檔、登入通道、session 與待處理請求。
start_muse_subscription_login取得 Meta 瀏覽器授權網址與代碼。
chat_with_muse把 workspace 訊息交給保留的 Muse session。
respond_to_muse傳回使用者選定的核准選項或答案。

06

資料與隱私

公開 Repo 包含程式碼與合成測試，不附帳號、credential、workspace 對應表、對話或真實用量快照。網站使用本機靜態素材，沒有分析追蹤或第三方字型請求。

使用時，資料存在哪裡？

Bridge 在使用者的系統資料目錄保存 workspace 與 session 的對應。可用 MUSE_BRIDGE_STATE_PATH 在本機改變位置，建議放在 Git repo 之外。

Status 與用量回覆會省略帳號名稱和 Email，診斷訊息會遮蔽常見 credential 格式。提示詞與選取的專案內容仍會由 Muse／Meta 處理，Muse Code 或 MCP client 也可能依自己的規則保留紀錄。

遮蔽範圍包含錯誤訊息、巢狀錯誤 details、回合結束的 error／reason，以及 protocol-error。正常對話與進度文字、待核准的實際操作、必要路徑、session／request／choice ID 與登入代碼會保留，MCP 回覆不能視為已全面匿名。PATH 搜尋只檢查執行權限，不會執行候選檔案。

reset_muse_session 只清除 Bridge 對應。請勿把 runtime state、log、匯出對話或含個資的截圖上傳公開 Repo。

07

常見問題

顯示找不到 Muse 執行檔，怎麼處理？

先在 Terminal 確認 muse --version 可執行。桌面 App 的 PATH 可能與 shell 不同；可在本機 MCP 環境設定 MUSE_BIN，指向官方 CLI 的執行檔。

已經登入，為什麼 Bridge 仍拒絕執行？

檢查 get_muse_status 回報是否為 accountLogin。若為 API-key 通道或未登入，請使用 start_muse_subscription_login 完成 Meta 瀏覽器授權，再重新查看狀態。

只有 skill，能直接使用 Muse 嗎？

Skill 提供操作流程，仍需要此 Repo 的 MCP server、Node.js 與官方 Muse CLI。建議在 Codex 安裝完整 plugin。

這是 Meta 或 OpenAI 官方 plugin 嗎？

這是獨立的社群整合，以 MIT 授權公開，與 Meta、OpenAI 沒有隸屬關係。官方 Muse CLI 與你的訂閱仍依 Meta 的規則運作。
